# АвтоКлюч — калькулятор стоимости авто с Copart/IAAI под ключ

> Бриф для Claude Code. Цель — не «форма с полями», а лучший в нише
> внутренний инструмент: быстрый, без ошибок в цифрах, приятный
> в ежедневном использовании. Детали UX/визуала, не описанные ниже
> буквально — на усмотрение реализации, в духе дизайн-референса
> (см. раздел 9). Название «АвтоКлюч» и весь текстовый контент сайта —
> плейсхолдеры, легко заменить на реальный бренд клиента.

## 1. Контекст

Команда перегоняет автомобили с американских аукционов Copart и IAAI
в Украину «под ключ» — от ставки на аукционе до цены на выходе
с таможни. Нужны два связанных продукта:

- **Внутреннее приложение** (SPA) — калькулятор стоимости для
  менеджеров и администратора. Клиентского доступа нет.
- **Публичный сайт** клиента — маркетинговая страница с тизером того
  же калькулятора, визуально согласованная с приложением (общая
  цветовая и шрифтовая система — см. `design-tokens.json`).

## 2. Стек

- **Frontend**: React (SPA), TypeScript.
- **Backend**: Node.js (Fastify/Express) либо Python (FastAPI) — выбрать
  то, что даёт более чистую и быструю реализацию.
- **БД**: PostgreSQL.
- **Деплой**: Docker-контейнер(ы) на Debian GCP-инстансе.
- **Секреты** (API-ключи) — только через переменные окружения, никогда
  в коде и никогда во фронтенд-бандле.

## 3. Данные о лоте (Copart / IAAI)

Официального публичного API у площадок нет.

- Поле ввода: номер лота (8 цифр) ИЛИ VIN.
- Кнопка «Подтянуть данные» — best-effort парсинг публичной страницы
  лота: марка/модель, год, объём двигателя, топливо, локация, тип
  кузова.
- Если не получилось — мягкий fallback на ручной ввод тех же полей
  с сообщением «Не удалось получить автоматически, заполните вручную»
  (без падения с ошибкой).
- Получение данных лота — отдельный сервис/модуль, заменяемый или
  отключаемый без изменений в остальной логике.
- Не логировать и не хранить ничего похожего на попытку обхода
  авторизации аукционов — только публичные страницы лотов.

## 4. Растаможка — готовый API

Официальный бесплатный API `baza-gai.com.ua` уже считает растаможку по
актуальному украинскому законодательству. Формулу не переизобретать.

```
GET https://baza-gai.com.ua/taxes
Headers:
  Accept: application/json
  X-Api-Key: <ключ из переменной окружения>

Параметры (car_type=car):
  price     — цена авто
  currency  — USD | EUR | UAH
  volume    — объём двигателя, л (например 2.0)
  motor     — petrol | diesel
  year      — год выпуска

car_type=electric: вместо volume/motor — power (кВт·ч)
car_type=hybrid:   только price/currency (фиксированный акциз)

Ответ: nds, duty, excise, pension_fund, result_price,
       result_price_usd / result_price_eur / result_price_uah
```

Обязательно:

- Проксировать вызов через бэкенд (ключ не должен попасть во фронтенд).
- Кешировать последний успешный ответ на конкретный расчёт — если API
  недоступен, показывать последнее значение с пометкой «не обновлено»
  и разрешать ручной override.
- Разрешить вручную поправить итоговую сумму растаможки поверх ответа
  API.

## 5. Поля калькулятора

| Поле | Источник по умолчанию | Ручное редактирование |
|---|---|---|
| Ставка | ввод пользователя | да, обязательное |
| Доставка | таблица тарифов (локация + тип авто) | да |
| Аукционный сбор | таблица тарифов (площадка + диапазон ставки) | да |
| Комплекс | настройки (значение по умолчанию) | да, на уровне расчёта |
| Растаможка | API baza-gai.com.ua (ставка/год/топливо/объём) | да, override |
| Вид авто | селект, определяет надбавку к доставке | — |
| Сертификация | настройки (значение по умолчанию) | да, на уровне расчёта |
| Комиссия | настройки (значение по умолчанию) | да, на уровне расчёта |
| Swift | % от (ставка + аукционный сбор), процент из настроек | да, сам процент |

Итог показывать двумя способами: постатейной разбивкой (для менеджера)
и одной крупной суммой (для скриншота клиенту).

## 6. Тарифы и настройки

- Раздел «Тарифы»: таблицы доставки и аукционного сбора редактируются
  прямо в интерфейсе (добавить / изменить / удалить строку). Без
  импорта-экспорта Excel на первом этапе.
- Раздел «Настройки»: значения по умолчанию для комплекса,
  сертификации, комиссии, процента Swift.
- Любое изменение тарифа или настройки фиксируется в истории (кто,
  когда, старое значение → новое). Это критично — нужно понимать,
  почему расчёт недельной давности отличается от сегодняшнего.

## 7. Пользователи и роли

- Логин/пароль. Роли минимум: **администратор** (тарифы, настройки,
  пользователи) и **менеджер** (расчёты, видит свою персональную
  скидку/наценку к доставке).
- Персональная скидка к доставке — в профиле пользователя,
  применяется автоматически.
- Клиентского доступа нет — расчёт уходит клиенту как
  скриншот/экспорт, вручную.

## 8. История расчётов

- Каждый сохранённый расчёт хранит: все использованные значения
  полей, курс валют на момент расчёта, кто считал, дату.
- Список с поиском/фильтром (марка, дата, менеджер).
- Открыть старый расчёт → посмотреть разбивку → скопировать в новый
  (пересчитать с текущими тарифами).

## 9. Дизайн-референс

Кликабельный дизайн-макет сайта и приложения (5 экранов: сайт,
вход, калькулятор, тарифы, история) уже сделан и служит визуальным
эталоном:

**https://claude.ai/code/artifact/f2c12799-ba18-409f-b045-ca1514ad5255**

Держать реализацию близко к нему: тёмная тема приложения, светлый
тёплый тон сайта, шрифтовая пара serif/sans/mono, единый акцентный
цвет, паттерн «карточка для клиента» под скриншот. Точные значения —
в `design-tokens.json` рядом с этим файлом. Названия ролей, копирайтинг
сайта и цифры (телефон, e-mail, статистика в квадратных скобках) —
плейсхолдеры, подставить реальные при наличии.

Ключевые UX-решения референса, обязательные к реализации:

- Мгновенный пересчёт всей суммы при изменении любого поля — без
  кнопки «Пересчитать».
- Отдельная «карточка для клиента» — визуально готовый к скриншоту
  блок с итоговой разбивкой (без внутренней методологии/источников),
  с кнопками «Скопировать разбивку» и «Сохранить PNG».
- Наглядная визуализация состава итоговой суммы (не просто список
  цифр) — например, сегментированная шкала по крупным статьям
  (ставка / доставка+сборы / растаможка / услуги).
- Горячие клавиши: поиск лота, сохранить расчёт, скопировать итог.
- Автосохранение черновика расчёта с индикатором «Черновик сохранён».
- Переключатель тёмной/светлой темы в приложении.

По пункту 8 исходного ТЗ — решение принимать самостоятельно, кратко
перечислить в конце работы, что добавлено сверх брифа и почему.

## 10. Порядок реализации (MVP → расширение)

1. MVP: форма расчёта, ручной ввод всех полей лота, растаможка через
   API baza-gai.com.ua, статичные суммы из конфига.
2. Тарифы и настройки — переезд в БД, редактирование через UI.
3. Пользователи, роли, персональные скидки.
4. История расчётов.
5. Автоподтяжка данных лота с Copart/IAAI с fallback на ручной ввод.
6. UX-улучшения из раздела 9 (мгновенный пересчёт, карточка для
   клиента, хоткеи, автосохранение, визуализация состава суммы, тема).

## 11. Сайт клиента (публичная часть)

Одностраничный лендинг, согласованный по стилю с приложением:

- Хиро с оффером и CTA на калькулятор.
- «Как это работает» — 5 шагов от лота до ключей.
- Тизер калькулятора — упрощённая версия расчёта в стиле тёмной темы
  приложения (та же типографика/акцент — визуальный мостик к
  приложению).
- Услуги, гарантии/цифры (сейчас как плейсхолдеры `[500+]`, `[7] лет`
  — заменить на реальные), финальный CTA, футер с контактами.

Полный текст и структура секций — в дизайн-референсе (артборд
«Сайт — главная»); переносить копирайтинг оттуда, не выдумывая новых
фактов сверх помеченных плейсхолдеров.
