# ТЗ: калькулятор стоимости авто с Copart/IAAI под ключ

## 1\. Цель проекта

Веб-приложение для расчёта полной стоимости доставки и растаможки автомобиля с американских аукционов (Copart, IAAI) "под ключ" — от ставки на аукционе до цены на выходе с таможни. Мультипользовательский режим: разные логины видят разные условия (скидки на доставку, роли).  
---

## 2\. Получение данных о лоте

### 2.1 Официальных публичных API у Copart и IAAI нет

Доступ для сторонних разработчиков не предоставляется — только партнёрские интеграции по коммерческому договору. Варианты:

| Вариант | Плюсы | Минусы |
| :---- | :---- | :---- |
| Ручной ввод полей | 100% надёжно, без рисков | Требует времени оператора |
| Сторонние скрейперы (Apify-акторы и т.п.) по номеру лота/VIN | Автоматизация | Нарушение ToS площадок, риск блокировки, может отвалиться без предупреждения |
| Партнёрский доступ к API (через брокера-партнёра Copart/IAAI) | Официально, стабильно | Обычно доступно только лицензированным дилерам-партнёрам, нужен отдельный договор |

Рекомендация: делать автоподтяжку данных с fallback на ручной ввод. Не завязывать бизнес-логику на то, что данные лота придут автоматически — только "если получилось, иначе руками".

### 2.2 Нужные поля с лота

* Номер лота (8 цифр) или VIN  
* Марка / модель / название  
* Год выпуска  
* Объём двигателя  
* Вид топлива (бензин / дизель / электро / гибрид)  
* Локация (штат/город аукциона — влияет на доставку)  
* Тип кузова / вид авто (влияет на надбавку к доставке)  
* Текущая ставка (если получится — предзаполнение поля "ставка")

---

## 3\. Растаможка — уже есть готовый честный API

baza-gai.com.ua предоставляет официальный бесплатный API (1000 запросов/мес, платно — больше) именно с калькулятором растаможки под украинское законодательство.  
Ключевой эндпоинт:  
GET https://baza-gai.com.ua/taxes  
Headers: Accept: application/json, X-Api-Key: \<ключ\>

Параметры для легкового авто (car\_type=car):

* price — цена авто  
* currency — USD / EUR / UAH  
* volume — объём двигателя, л (например 2.0)  
* motor — petrol / diesel  
* year — год выпуска

Для электро (car\_type=electric): вместо volume/motor — power (мощность, кВт·ч, по факту тянет за собой акциз от ёмкости батареи).  
Для гибрида (car\_type=hybrid): только базовые параметры — фиксированный акциз \~100 EUR (если ДВС используется только для подзарядки батареи; "полноценные" гибриды типа Prius считаются как обычные ДВС-авто).  
Ответ:  
{  
  "nds": 2260,           // НДС  
  "duty": 1000,          // пошлина  
  "excise": 300,         // акциз  
  "pension\_fund": 339,   // пенсионный фонд  
  "all\_fees\_with\_pension\_fund": 3899,  
  "result\_price": 13899.0,  
  "result\_price\_usd": 16540,  
  "result\_price\_uah": 464922  
}

Это готовая замена вашей ручной формуле — не нужно поддерживать коэффициенты по годам/топливу самим, площадка обновляет их по факту изменений законодательства. Опционально можно закешировать ответы на своей стороне и оставить ручной override на случай, если API недоступен или нужно скорректировать вручную.

## 4\. Поля калькулятора

| Поле | Источник | Редактируется вручную |
| :---- | :---- | :---- |
| Ставка | Ввод пользователя | Да |
| Доставка | Таблица (по локации \+ виду авто) | Да |
| Аукционный сбор | Таблица (по цене ставки, площадке) | Да |
| Комплекс | Статичная сумма | Да |
| Растаможка | Формула / API baza-gai (ставка, год, топливо, объём) | Да (override) |
| Вид авто | Селект — влияет на надбавку к доставке | — |
| Сертификация | Статичная сумма | Да |
| Комиссия | Статичная сумма | Да |
| Свифт | % от (ставка \+ аукционный сбор) | Да (сам процент) |

Таблицы доставки и аукционного сбора — редактируемые пользователем сущности (не хардкод), с историей изменений (когда и кто поменял ставку) — это защитит от путаницы, если несколько человек правят таблицы.  
---

## 5\. Мультипользовательский режим (сразу, по вашему решению)

* Логин/пароль или ID.  
* Роли: администратор (правит таблицы, формулы, сборы), менеджер (считает для клиентов, видит свою скидку), клиент (видит только итоговую цену, без внутренних полей — опционально на будущее).  
* У каждого пользователя — персональная скидка/наценка к доставке, привязанная к профилю.  
* Логирование: кто и когда изменил таблицу доставки/сборов.

---

## 6\. Что можно добавить сверх базового ТЗ (отстройка от конкурентов)

* История расчётов с датой и курсом валют на момент расчёта.  
* Импорт таблиц доставки/сборов из Google Sheets/Excel одной кнопкой.  
* PDF коммерческое предложение клиенту одним кликом (без внутренних полей).  
* Отслеживание активных лотов на аукционе (если авто ещё не куплено) с уведомлением о росте ставки.  
* Разделение "себестоимость" / "цена для клиента" с явной маржой.  
* Отдельные строки: страховка фрахта, портовый хендлинг, экологический сбор (если не входят в текущую растаможку).  
* Архитектура с заделом под другие площадки (Manheim, Copart UK/Canada) без переписывания ядра.

## 7\. Решённые вопросы

1. Таблицы доставки/сборов — редактируются прямо в приложении (раздел "Настройки" или отдельная вкладка "Тарифы"), без привязки к внешнему Excel/Google Sheets. Хранятся в БД, с историей изменений.  
2. Комплекс / сертификация / комиссия — статичные суммы по умолчанию, но свободно редактируются прямо в калькуляторе на конкретном расчёте или централизованно во вкладке "Настройки" (правка в настройках меняет значение по умолчанию для новых расчётов, ручная правка в конкретном расчёте — только для него).  
3. Доступ — только для внутренней команды (менеджеры \+ админ). Клиентского доступа нет; готовые расчёты передаются клиенту как скриншот/PDF вручную.  
4. Стек — не принципиально, выбираем оптимальный под задачу.

---

## 8\. Рекомендация по стеку

Drupal здесь избыточен — это CMS для контентных сайтов, а калькулятор — прикладной инструмент с формами, таблицами и расчётами в реальном времени. Оптимальнее:

* Frontend: React (SPA) — быстрый интерактивный ввод/пересчёт полей без перезагрузки страницы, легко встраивается таблица тарифов с inline-редактированием.  
* Backend: Node.js (Express/Fastify) или Python (FastAPI) — тонкий слой: авторизация, хранение тарифов, проксирование запроса к baza-gai.com.ua API (чтобы API-ключ не светился на фронте), логика роли/скидок.  
* База данных: PostgreSQL — таблицы тарифов, пользователи, история расчётов и история изменений тарифов.  
* Хостинг: один из ваших GCP Debian-инстансов, через Docker — вписывается в то, чем вы уже пользуетесь.

Такой стек даёт: быстрый MVP (простой личный калькулятор) с прямым путём расширения до мультипользовательской версии с ролями и историей — без смены архитектуры на полпути.  
---

## 9\. Предлагаемый порядок разработки (MVP → расширение)

1. MVP: форма расчёта с ручным вводом всех полей, статичные суммы редактируются в коде/конфиге, растаможка — прямой вызов baza-gai.com.ua API.  
2. Тарифы в БД: таблицы доставки и аукционного сбора переезжают в БД с редактированием через UI ("Настройки").  
3. Мультипользовательский слой: логин, роли, персональные скидки к доставке.  
4. История расчётов: сохранение каждого расчёта с датой, курсом, кто считал.  
5. Автоподтяжка данных лота: интеграция парсинга по номеру лота/VIN с ручным fallback.  
6. Доп. фичи: PDF-экспорт для внутреннего архива, отслеживание активных лотов, импорт тарифов из Excel.

# Дополнение к ТЗ: доп. поля калькулятора

Добавить к основному расчёту (файл claude-code-brief.md), не меняя уже описанную структуру:

Поле Логика Редактирование  
Курс валют (USD→UAH/EUR) Подтягивать автоматически (НБУ API или любой публичный курс), с возможностью зафиксировать вручную на конкретный расчёт Да, override  
Страховка фрахта Статичная сумма или % от ставки (уточнить у пользователя как считается) Да  
Портовые расходы (хендлинг) Статичная сумма из настроек, отдельно от "Доставки" Да  
Экологический сбор Статичная сумма или % — проверить сначала, не включён ли уже в ответ API baza-gai.com.ua (поле результата может уже содержать этот сбор внутри растаможки — не задвоить) Да  
Маржа/наценка Скрытое поле, видно только менеджеру/админу, не выводится в клиентский скриншот. Итог считать в двух видах: "себестоимость" (без маржи) и "цена клиенту" (с маржой) Да

Все новые поля — такие же настраиваемые значения по умолчанию во вкладке "Настройки", как комплекс/сертификация/комиссия, с той же историей изменений.

Если поле не актуально для конкретного расчёта (например, страховка не нужна) — должна быть возможность обнулить/выключить его для этого расчёта, а не только менять сумму.
