# Промпт/ТЗ для Claude Code: калькулятор стоимости авто с Copart/IAAI

## Контекст

Ты строишь внутренний веб\-инструмент для команды, которая перегоняет автомобили с американских аукционов Copart и IAAI в Украину/Европу под ключ. Инструмент считает полную стоимость авто: от ставки на аукционе до цены "под ключ" на выходе с таможни. Пользователи — менеджеры компании (не клиенты), поэтому калькулятор внутренний, без публичного доступа.

**Задача не "сделать форму с полями", а сделать лучший в своей нише инструмент** — тот, которым приятно и быстро пользоваться каждый день, который экономит время и не даёт ошибиться в цифрах. Ниже — обязательные требования, но в деталях UX, визуала и мелких удобств — предлагай свои решения. Если видишь способ сделать удобнее, быстрее или красивее, чем описано — делай так и кратко объясни, почему.

---

## 1\. Стек

- **Frontend**: React (SPA), TypeScript.  
- **Backend**: Node.js (Fastify или Express) либо Python (FastAPI) — на твоё усмотрение, выбери то, что даст более чистую и быструю реализацию.  
- **БД**: PostgreSQL.  
- **Деплой**: Docker-контейнер(ы), рассчитан на размещение на Debian GCP-инстансе.  
- Секреты (API-ключи) — через переменные окружения, никогда не в коде и не на фронте.

---

## 2\. Данные о лоте (Copart / IAAI)

Официального публичного API у Copart и IAAI нет. Реализуй так:

- Поле ввода: номер лота (8 цифр) ИЛИ VIN.  
- Кнопка "Подтянуть данные" — best-effort попытка получить с публичной страницы лота: марка/модель, год, объём двигателя, тип топлива, локация, тип кузова.  
- Если подтянуть не удалось (сайт изменился, защита блокирует и т.п.) — не падать с ошибкой, а мягко переключаться на ручной ввод этих же полей с сообщением "Не удалось получить автоматически, заполните вручную".  
- Архитектурно вынеси получение данных лота в отдельный сервис/модуль, чтобы его можно было заменить или отключить без изменений в остальной логике.  
- Не храни и не логируй ничего, что похоже на попытку обойти авторизацию аукционов — только публичные страницы лотов.

## 3\. Растаможка — используй готовый API

Официальный бесплатный API **baza-gai.com.ua** уже считает растаможку по актуальному украинскому законодательству. Не изобретай формулу заново.

GET https://baza-gai.com.ua/taxes

Headers:

  Accept: application/json

  X-Api-Key: \<ключ из переменной окружения\>

Параметры (car\_type=car):

  price     — цена авто

  currency  — USD | EUR | UAH

  volume    — объём двигателя, л (например 2.0)

  motor     — petrol | diesel

  year      — год выпуска

Для car\_type=electric: вместо volume/motor — power (кВт·ч)

Для car\_type=hybrid: только price/currency (фиксированный акциз)

Ответ содержит `nds`, `duty`, `excise`, `pension_fund`, `result_price`, `result_price_usd/eur/uah` — используй их напрямую.

Обязательно:

- Проксируй вызов через бэкенд (ключ не должен попадать во фронтенд-бандл).  
- Закешируй последний успешный ответ на конкретный расчёт — если API временно недоступен, показывай последнее значение с пометкой "не обновлено" и разрешай ручной override.  
- Дай пользователю возможность вручную поправить итоговую сумму растаможки поверх того, что вернул API (это его законное право — цифры иногда расходятся с реальной практикой на месте).

## 4\. Поля калькулятора

| Поле | Источник значения по умолчанию | Ручное редактирование |
| :---- | :---- | :---- |
| Ставка | ввод пользователя | да, обязательное поле |
| Доставка | таблица тарифов (локация \+ тип авто) | да |
| Аукционный сбор | таблица тарифов (площадка \+ диапазон ставки) | да |
| Комплекс | настройки (значение по умолчанию) | да, на уровне расчёта |
| Растаможка | API baza-gai.com.ua (ставка/год/топливо/объём) | да, override |
| Вид авто | селект, определяет надбавку к доставке | — |
| Сертификация | настройки (значение по умолчанию) | да, на уровне расчёта |
| Комиссия | настройки (значение по умолчанию) | да, на уровне расчёта |
| Свифт | % от (ставка \+ аукционный сбор), процент из настроек | да, сам процент |

Итог показывать сразу двумя способами: постатейной разбивкой (что видит менеджер) и одной крупной итоговой суммой (что удобно кинуть в скриншот клиенту).

---

## 5\. Тарифы и настройки

- Отдельный раздел "Тарифы": таблицы доставки и аукционного сбора редактируются прямо в интерфейсе (добавить/изменить/удалить строку), без экспорта-импорта Excel на первом этапе.  
- Отдельный раздел "Настройки": значения по умолчанию для комплекса, сертификации, комиссии, процента свифта.  
- Любое изменение тарифа или настройки — фиксируется в истории (кто, когда, старое значение → новое). Это критично: цифры меняются часто, и должна быть возможность понять, почему расчёт неделю назад отличается от сегодняшнего.

---

## 6\. Пользователи и роли

- Логин/пароль, роли минимум: **администратор** (правит тарифы, настройки, пользователей) и **менеджер** (считает расчёты, видит свою персональную скидку/наценку к доставке).  
- Персональная скидка к доставке хранится в профиле пользователя и автоматически применяется при расчёте.  
- Клиентского доступа нет — расчёты уходят клиенту как скриншот/экспорт, вручную.

---

## 7\. История расчётов

- Каждый сохранённый расчёт хранит: все использованные значения полей, курс валют на момент расчёта, кто считал, дату.  
- Список прошлых расчётов с поиском/фильтром (по марке, дате, менеджеру).  
- Возможность открыть старый расчёт, посмотреть разбивку, скопировать в новый (пересчитать с текущими тарифами).

---

## 8\. Дай волю креативности

Помимо всего перечисленного — сделай это лучшим калькулятором такого рода в интернете. Подумай сам и предложи (реализуй, если это не ломает сроки и архитектуру):

- Такой UX, чтобы весь расчёт пересчитывался мгновенно при изменении любого поля, без кнопки "Пересчитать".  
- Продуманный дизайн для расчёта, который менеджер снимает скриншотом и отправляет клиенту — чтобы он сразу выглядел презентабельно, без необходимости обрабатывать его отдельно.  
- Приятные мелочи: горячие клавиши, автосохранение черновика расчёта, копирование итоговой разбивки в буфer одной кнопкой, тёмная тема.  
- Любые твои идеи по визуализации (например, наглядно показать, из чего складывается итог — не просто таблица цифр).

Не спрашивай разрешения на каждую творческую деталь — прими решение сам и коротко перечисли, что добавил сверх ТЗ и почему, в конце работы.

---

## 9\. Порядок реализации

1. MVP: форма расчёта, ручной ввод всех полей лота, растаможка через API baza-gai.com.ua, статичные суммы из конфига.  
2. Тарифы и настройки — переезд в БД с редактированием через UI.  
3. Пользователи, роли, персональные скидки.  
4. История расчётов.  
5. Автоподтяжка данных лота с Copart/IAAI с fallback на ручной ввод.  
6. Всё, что предложишь сам по пункту 8\.
